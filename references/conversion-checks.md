# Pick the right surface guide

Use the guide for the step being changed. Read the full guide before giving a full audit of that surface. Read a second guide when an element sits inside another, such as a form in a popup.

| Step | Guide | Check beyond the first tap |
|---|---|---|
| Home, landing, pricing, feature, content | [Pages](surfaces/pages.md) | Useful leads, buyers, or value at the chosen horizon |
| Signup, quiz, account access | [Signup and quiz](surfaces/signup.md) | Valid access and first value |
| Lead, demo, contact, survey, checkout fields | [Forms](surfaces/forms.md) | Useful records and later results |
| Popup, banner, modal | [Popups](surfaces/popups.md) | Extra results and lost page completions |
| In-product pricing, limits, trial, upgrade, payment | [Paywalls](surfaces/paywalls.md) | Paid result, correct access, refunds, later value |
| Setup, first use, stalled and returning users | [Onboarding](surfaces/onboarding.md) | First value, time to value, later use |
| Delivery, booking, confirmation, recovery, later use | [After purchase](post-purchase.md) | Delivery, held calls, paid sales, or useful return |

Write one line per change: which check changed or confirmed the idea, why, what is evidence, and what is still a guess.

These guides help frame the spec and ask useful questions. They do not replace a skill needed for deep design, test design, tracking, billing, price strategy, or cause analysis. Use [limits](limits.md) when the task crosses that line.

Never copy a fixed conversion benchmark, field-count penalty, campaign cutoff, reminder cadence, holdout, or test length as the right rule for this project.
