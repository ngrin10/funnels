# Onboarding and first value

Ask what useful thing the person should achieve first. A tour completed or an account created may not be that result.

## Map the path to value

| Step | What the person does | Why needed before value | Required input or permission | Next step | Failure / skip / resume |
|---|---|---|---|---|---|

Look for proof of what successful users do, but do not turn a pattern into a proven cause. If first value is unknown, ask the product owner and mark it as a proposal until checked.

Compare a direct start, guided setup, and an example or demo only when those options fit the real product. Do not force one path for every user. Separate new users from returning people, buyers from free users, and roles with different rights.

## Make the next action useful

Use an empty state to explain the task, show the kind of result, and offer a real first action. Label sample data. Do not let a fake result look like the user's own progress.

Use a checklist only when there are real steps to track. Order steps by dependencies and first value. Keep optional work optional. A tour should be brief, easy to leave, and limited to what the person needs now. Do not show it again because one event was missed.

## Help stalled and returning people

Define what counts as stalled using a real state and time rule. Say who gets help, which channel can be used, what ends the message, and what happens after they return. Do not keep sending reminders after the task is done.

Let returning people resume where it is useful. Explain expired setup, missing permissions, changed plans, and lost connections. Keep data and state rules clear across devices.

## Measure and prove

Define the start, first-value event, time to value, later return, and completion of each required step. Keep setup completion separate from value. Split groups only when the data supports that read.

Check fresh and returning accounts, skipped steps, failures, permission denial, phone layout, and resume. State what was actually tested. Use a tracking or test skill for new measurement work or claims about what causes retention.
