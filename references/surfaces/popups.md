# Popups, banners, and modals

First ask why this should interrupt the person at this point. A click, task limit, page context, or past action can give a reason; a timer alone does not prove need.

## Fill the display rules

| Rule | What to state |
|---|---|
| Purpose | What the person gains and the one main action |
| Entry | Exact event or condition that makes it appear |
| Who sees it | Allowed group, plan, device, and page |
| Who does not | Completed users, recent dismissals, conflicting flows, or other exclusions |
| Timing and repeat | Delay if any, max exposure, dismiss cooldown, and reset rule |
| Exit | Close, decline, outside tap, Escape, success, and failure behavior |
| Priority | What wins if two messages qualify at once |
| Data | What state is stored, where, and for how long |

These are project choices, not fixed best-practice numbers. Ask for missing choices or mark proposed values clearly.

## Keep the ask clear

Use a benefit that fits the current task. Show essential terms. Keep the decline plain and easy to find. Do not use guilt, false urgency, or a hidden close button. Do not trap someone by changing the browser's back action to force an offer.

For capture, show what they receive and how it is delivered. For a promo, check eligibility, total cost, expiry, redemption, and whether it is really available. For an announcement, a banner may fit better than a blocking modal.

## Check the whole page

Avoid covering the main form, payment, recovery, or critical task without a real reason. Decide which message has priority. Remember a dismissal across the places where the user expects it to hold. Define behavior when storage is blocked or the person uses another device.

On open, move focus into the dialog. Keep keyboard focus inside a blocking dialog. Support the allowed close actions and return focus to the starting control. Give the dialog a name. Check the smallest phone, scroll, zoom, long text, and keyboard.

## Measure the tradeoff

Define eligible views, impressions, submits, dismissals, and later results. More popup submits may come with fewer page completions. Include that loss in the review. Check events for reopen and repeat sessions without storing sensitive answers.
