# Plain names for needed terms

Use plain words first. Keep a technical name when the builder needs the exact name, and explain it once.

| Term | Plain meaning |
|---|---|
| Baseline | The number before the change |
| Metric | The number we use to judge it |
| Cohort | People grouped by the same start time or rule |
| Denominator | The full group used for a rate |
| Numerator | People or things in that group that did the action |
| Event | A named record that something happened |
| Property | A field saved with that record |
| Dedupe | Count the same action only once |
| Trigger | What makes the screen or message appear |
| Segment | People who match a set of rules |
| Holdout or control | People who keep the old version for a test |
| Variant | A version being tested |
| Assignment unit | Whether a person, account, or another unit gets a test version |
| Guardrail | Another check that tells us if the change causes harm |
| Feature flag | A switch that turns a change on or off |
| Rollback | Turn off or undo the change and check the old flow |
| Acceptance check | What the builder must show to prove the work is done |
| Data contract | The inputs and outputs a part of the system must use |
| Source of truth | The agreed record to update and build from |
| Causal claim | A claim that one thing made another thing happen |
| MEASURED | Checked in a system, with the rules and date named |
| STATED | Someone reported it; it was not checked here |
| MODELED | Calculated from named inputs; not an observed result |
| NOT KNOWN | Missing; say how to find it and what it blocks |
| NEEDS SKILL | This part needs a method the current skill does not have |

Do not hide uncertainty behind a simpler word. "We don't know why" is clearer than a confident guess.
